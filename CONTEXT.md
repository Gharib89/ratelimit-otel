# ratelimit-otel

A Claude Code plugin that exports **rate-limit window utilization** as OTLP. Claude Code's own OTel exporter ships eight metrics and none of them carries this; the number exists only behind `/usage`. The plugin replaces a per-machine statusline wrapper and its installer, so a seat needs no Node on PATH, no statusline and no local artifact: the endpoint and the bearer are read from the console telemetry env block at send time ([ADR-0004](docs/adr/0004-transport-reads-the-console-env-block.md)).

Scope discipline: anything Claude Code already exports is out of scope here. Cost in particular is available on `$.session.usage()` and is deliberately not emitted ([ADR-0001](docs/adr/0001-telemetry-contract.md)).

## Ubiquitous language

Use these terms in issue titles, test names, metric labels and ADRs. Where a term below differs from the one a neighbouring system uses, this file wins inside this repo and the boundary is named in the entry.

- **Window** — a rate-limit period the account is measured against. Two kinds, `five_hour` and `seven_day`, emitted as `5h` and `7d`. A window is identified by its `resets_at`, not by its kind alone: when a window rolls over, the next one is a new series, and reading it as the same series turns a rollover into a drop to zero.
- **`spend_limit`** — not a window. It arrives in the same `rateLimits` array in place of the two time windows behind a gateway provider, and it measures dollars. It is skipped, never mapped onto a window spelling.
- **Utilization** — `percentUsed` for a window, 0 to 100. The single quantity this plugin exists to export.
- **Account-wide** — true of every rate-limit reading. Concurrent sessions on one account all report the same numbers, so readings are aggregated with **max** per `(account, kind, resets_at)` and never summed. "Per session" is not a thing a window has. Aggregation belongs to the consumer: this repo delivers every movement of every session and neither deduplicates across sessions nor smooths ([ADR-0003](docs/adr/0003-sample-every-session-with-an-identity-ladder.md), [ADR-0005](docs/adr/0005-deliver-on-movement.md)).
- **Sample** — one read of `$.session.usage()` and the OTLP record it produces. Taken when the engine measures the session (pushed after each main-thread turn and whenever a window moves a whole point, a subagent's response included) and when a session ends, and delivered only on **movement** ([ADR-0005](docs/adr/0005-deliver-on-movement.md)). A window reflects the last API response and has nothing to report before one lands. A `/clear` ends a session too, measured, so it takes one as well.
- **Movement** — a window has moved when its whole-point utilization or its `resets_at` differs from the last delivery that landed for this session, or it is newly present. A sample is delivered only on movement ([ADR-0005](docs/adr/0005-deliver-on-movement.md)).
- **Identity ladder** — the three-rung read that gives a sample its `user.email`: `.claude.json` in the directory Claude Code keeps it in (`CLAUDE_CONFIG_DIR`, else `HOME`, else `USERPROFILE`), then `OTEL_RESOURCE_ATTRIBUTES`, then `CLAUDE_USER_EMAIL`. A CI run has no `oauthAccount` on disk, and a sample with no email is still emitted. The ladder governs the email alone: `user.account_id` is read off that same file whenever the file carries one, because neither later rung can supply it.
- **Seat** — one machine-and-user running Claude Code. The unit the fleet is counted in and the unit a config reaches.
- **Instrumentation scope** — the OTel scope the records carry, `cc-otel.plugin`. A boundary term: the downstream collector keeps only records whose metric prefix it already allows and drops the rest as foreign, silently, so the emit contract is held with a system outside this repo.
- **Transport** — how a sample leaves the process: a POST of OTLP JSON to `<endpoint>/v1/metrics`, the endpoint and the `Authorization` header read at send time from the **console telemetry env block**, the org console policy's env settings that also configure Claude Code's own exporter. The plugin holds no endpoint and no credential of its own, and a scope the block does not reach sends nothing ([ADR-0004](docs/adr/0004-transport-reads-the-console-env-block.md)).
- **Manifest version** — the `version` string in `plugin/.claude-plugin/plugin.json`. Load-bearing, not bookkeeping: the fleet's rollout is measured off the `plugin_loaded` event's version, so a release that does not bump it is unmeasurable. Several plugins in production report an empty version. `.github/workflows/release.yml` is what writes it, on a push to `main`, grading the bump from the squash subject's Conventional type; a PR never carries a version edit.
- **Marketplace entry** — the object in `.claude-plugin/marketplace.json` naming this plugin. Its `name` and the marketplace's own `name` are the coordinate a seat installs by, `ratelimit-otel@ratelimit-otel`, and the pair the org console pins in `extraKnownMarketplaces` and `enabledPlugins`; its `source` is the path the plugin body is read from, `./plugin`. It carries no `version`: the **manifest version** is the single copy, and `claude plugin tag` refuses a release where the two disagree. It is the route a developer seat installs by, not the fleet's ([ADR-0006](docs/adr/0006-distribute-as-a-pinned-release-archive.md)).
- **Release archive** — the zip of `plugin/` attached to the GitHub Release for a tag, with `.claude-plugin/plugin.json` at its root, named by the **manifest version** and published with its `sha256`. The fleet's install route: a seat fetches one HTTPS file and needs no git ([ADR-0006](docs/adr/0006-distribute-as-a-pinned-release-archive.md)).
- **Silent no-op** — the plugin's characteristic failure. Without `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` the hooks module does not load and nothing reports it: no error, no log, no records. The flag now ships fleet-wide in the org console policy env block, but it remains the first hypothesis for "nothing happened", not the last. It has a second shape: where the console policy does not reach a scope, `OTEL_EXPORTER_OTLP_ENDPOINT` is unset or empty, the sample is skipped rather than retried, and again nothing reports it ([ADR-0004](docs/adr/0004-transport-reads-the-console-env-block.md)).

## Decisions

The emit contract is settled. Read these before changing anything that leaves the process:

- [ADR-0001](docs/adr/0001-telemetry-contract.md) — metric names, values, scope and attributes. Names are a contract with the collector, and a wrong one is dropped silently rather than rejected.
- [ADR-0002](docs/adr/0002-emit-both-the-instant-and-the-countdown.md) — `reset_in_seconds` stays a metric and `resets_at` is added as an attribute, so the producer can change before the consumer. Amended: the countdown rounds up, so the reconstruction bins to its own window.
- [ADR-0003](docs/adr/0003-sample-every-session-with-an-identity-ladder.md) — sample every session including CI, with an identity ladder. Amended: a cloud session delivers where its environment's setup script installs the plugin and its network reaches the collector; a session ending is sampled. Its triggers and delivery floor are superseded by ADR-0005.
- [ADR-0005](docs/adr/0005-deliver-on-movement.md) — deliver only on movement, pushed by `session.measure` and taken again at `session.end`; the POST is detached everywhere but at exit. No clock, no floor, no `$.store`.
- [ADR-0004](docs/adr/0004-transport-reads-the-console-env-block.md) — the transport reads the console telemetry env block, POSTs OTLP JSON, and skips where there is no endpoint. No config artifact, no credential in this repo.
- [ADR-0006](docs/adr/0006-distribute-as-a-pinned-release-archive.md) — the fleet installs a pinned release archive over HTTPS, named by URL and `sha256` in the console; the repo's marketplace stays for developer seats.

## Where this is going

Build for **one seat**: a version installed from a pinned **release archive** and correct on one machine. The cc-otel database tickets are held until real rows land in `raw.metrics`, and the schema is decided from those rows rather than ahead of them.

Distribution to the fleet runs through the **release archive** ([ADR-0006](docs/adr/0006-distribute-as-a-pinned-release-archive.md)). The org console declares the marketplace inline in `extraKnownMarketplaces` and names one release archive by URL and `sha256`, so a seat needs neither git nor SSH, and a version reaches the fleet only when the operator edits that entry. `.claude-plugin/marketplace.json` stays for a developer seat: `claude plugin marketplace add <this repo>` then `claude plugin install ratelimit-otel@ratelimit-otel` installs at user scope, and `--plugin-dir` stays the way to run an unmerged branch.

The console entry is the operator's to write, not this repo's. The policy env block already carries `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS`. One seat runs a pinned release archive alone first; the fleet follows after a quiet period.
